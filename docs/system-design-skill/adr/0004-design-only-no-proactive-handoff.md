# Keep `design` Design-Only

The `design` skill should stop at system and service design artifacts. It should not proactively hand off to `plan`, `prototype`, or `build`; follow-on work happens only when the user explicitly asks for it.

## Consequences

The skill's completion criteria should focus on approved design documents, resolved or recorded open questions, and clear remaining risks. It should avoid turning an approved design conversation into implementation planning unless requested.
