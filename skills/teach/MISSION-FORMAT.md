# MISSION.md Format

`MISSION.md` captures the reason the user is learning this topic. Every teaching
decision traces back to it.

```md
# Mission: {Topic}

## Why

{1-3 sentences. The concrete real-world goal. What changes in their work or life
when they have this skill?}

## Success looks like

- {A specific, observable thing the user will be able to do}

## Constraints

- {Time, budget, prior commitments, learning preferences}

## Out of scope

- {Adjacent topics they do not want to chase right now}
```

## Rules

- One mission per teaching project. Two unrelated topics are two projects.
- Concrete over abstract. "Ship a Rust CLI to my team" beats "learn Rust."
- If the user cannot articulate why, interview them before writing anything.
- When the goal moves, update this file.
- Keep it short. Past a screen, it has stopped being a compass.
